## Critical GridKit Build Flags
- **`-DCMAKE_BUILD_TYPE=RelWithDebInfo`** — NOT Release. O3 over-optimizes LLVM IR,
  making `__enzyme_todense` untraceable. This was the root cause of all Enzyme failures.
- `--gcc-toolchain=${GCC13_ROOT}` in CXX/C flags — **clang only**, not gcc. Clang picks
  up GCC 12 by default on Kestrel; this forces GCC 13 headers/libstdc++.
  Script 1 uses gcc to build LLVM itself and must NOT pass this flag.
- `-Wl,-rpath,${GCC13_LIBDIR}` — bakes GCC 13 lib path into binaries so GLIBCXX_3.4.29
  is found at runtime
- No `cray-libsci` module — it pins PE_LIBSCI_GENCOMPILERS_GNU_x86_64=12.1, breaking
  the GCC 13 environment

## Key Modules
- `gcc-stdalone/13.1.0` — GCC 13, needed for `<format>` header and GLIBCXX_3.4.29
- `cmake/3.29.2` — RHEL8 only; use `cmake/3.27.9` on RHEL9

## IPOPT
- Previous build: MA27/MA57 via dlopen (HSL loader) — broken, `libhsl.so` doesn't exist
- Current: MUMPS via ThirdParty-Mumps (open source). Links `local/lib/libcoinmumps.so`
- Needs `netlib-lapack/3.11.0-gcc` module at build time


## Docs — MkDocs (primary)
- `build_mkdocs.sh` — full build script; run from any shell on Kestrel
  - Requires conda env `f-py312-basic` (`module load conda && conda activate f-py312-basic`)
    Any Python 3.8+ env works if recreating from scratch.
  - Auto-installs on first run (idempotent): `mkdocs`, `mkdocs-material`, `mkdocs-awesome-pages-plugin`
    (`pip install -q ...` — skipped if already present). No other packages needed.
  - Symlinks GridKit source tree into `mkdocs/docs/`
  - Writes `mkdocs/mkdocs.yml` and `mkdocs/hooks.py` fresh each run
  - Output: `mkdocs-site/`
- **hooks.py** (generated by build script) — pre-processes Markdown before Python-Markdown:
    1. Converts ` ```math...``` ` fences (and ` ``` math ` with space) → `$$...$$` blocks,
       with blank lines around each block so consecutive equations render separately
    2. Collapses internal blank lines inside math blocks (PSS1A source bug workaround)
    3. Inserts blank line before lists that immediately follow paragraph text
       (Python-Markdown requires this; GitHub GFM does not)
    4. Rewrites figure paths `../../../docs/Figures/` → depth-relative path per page
- **mkdocs.yml** key settings:
    - `use_directory_urls: false` — enables local file browsing without a server
    - `pymdownx.arithmatex` with `generic: true` — math via `$$...$$` and `$...$`
    - MathJax 3 CDN for rendering
    - `awesome-pages` plugin — respects `.pages` ordering files in source tree
- **Do NOT double backslashes** — arithmatex passes `\begin`, `\dfrac`, `\\` etc.
  through unchanged; doubling them corrupts all equations

## Installation Problems & Fixes

### `<format>` header not found / GCC 12 vs GCC 13
- `<format>` (C++20) requires GCC 13+. Kestrel's default compiler is GCC 12.
- Fix: load `gcc-stdalone/13.1.0` and pass `--gcc-toolchain` to clang so it picks up
  GCC 13 headers and `libstdc++` instead of GCC 12.
- Also bake GCC 13 lib path into binaries with `-Wl,-rpath,${GCC13_LIBDIR}` so
  `GLIBCXX_3.4.29` is found at runtime without needing to `module load` manually.
- Without `-rpath`, running PDSim on a node with default modules fails with:
  `libstdc++.so.6: version GLIBCXX_3.4.29 not found`

### Why LLVM 16 had to be built from source
- Kestrel has an `llvm/16` module, but it was built **without `LLVM_ENABLE_RTTI=ON`**.
- Enzyme requires RTTI to be enabled in the LLVM it links against; without it, linking
  Enzyme produces undefined symbol errors.
- Fix: build LLVM 16.0.6 from source with `LLVM_ENABLE_RTTI=ON` → `llvm/16.0.6/`.

### `--gcc-toolchain` is a clang flag, not a gcc flag
- Script 1 uses gcc to compile LLVM itself. Passing `--gcc-toolchain` to gcc causes:
  `gcc: error: unrecognized command-line option '--gcc-toolchain=...'`
- Fix: do NOT pass `--gcc-toolchain` in script 1 (gcc compiler). Only pass it in
  scripts 2-6 where clang is the compiler.

### `RelWithDebInfo` vs `Release` for Enzyme / `__enzyme_todense`
- Building GridKit with `-DCMAKE_BUILD_TYPE=Release` (O3) caused Enzyme's
  `__enzyme_todense` to silently fail — the LLVM IR was too aggressively optimized for
  Enzyme to trace through.
- Fix: use `RelWithDebInfo` (O2 + debug info). This was the root cause of all
  unexplained Enzyme failures before it was identified.

### Enzyme sparse limitations
- Enzyme's sparse-AD support is still experimental. Some sparse Jacobian patterns that
  work analytically would silently produce zeros or wrong values.
- Workaround: fall back to dense finite differences for those components, or restructure
  the computation to avoid the problematic patterns.

### `cray-libsci` module conflict
- Loading `cray-libsci` sets `PE_LIBSCI_GENCOMPILERS_GNU_x86_64=12.1`, which pins
  the Cray PE to GCC 12 and breaks the GCC 13 toolchain.
- Fix: do NOT load `cray-libsci`. Use `netlib-lapack/3.11.0-gcc` for LAPACK instead.
- SuiteSparse: `-DBLA_VENDOR=CRAY` fails with `Could NOT find BLAS`. Use `netlib-lapack/3.11.0-gcc`.
- SuiteSparse 7.8.2: `-DSUITESPARSE_USE_SPEX=OFF` is ignored; SPEX is controlled via
  `SUITESPARSE_ENABLE_PROJECTS`. Explicitly list only the needed components (exclude `spex`,
  `graphblas`, `lagraph`, `paru` which have heavy external deps not on Kestrel):
  `suitesparse_config;amd;btf;camd;ccolamd;colamd;cholmod;klu;umfpack;ldl;rbio`

### SUNDIALS: KLU include path
- SuiteSparse 7.8.2 installs headers to `include/suitesparse/` (not `include/` directly).
- SUNDIALS cmake KLU check fails with `Size of 'SuiteSparse_long' is .` when the include
  dir is wrong (cannot find `SuiteSparse_config.h` to determine type sizes).
- Fix: set `-DKLU_INCLUDE_DIR=$SUITESPARSE_PREFIX/include/suitesparse`

### Experimental examples fail to link: `liblapack.so.3` not found
- IPOPT's `libipopt.so` depends on `liblapack.so.3` at link time.
- Script 6 must load `netlib-lapack/3.11.0-gcc` so the linker can find it.
- Without it, the 4 Experimental examples (`DynamicConOpt`, `GenConstLoad`,
  `GenInfiniteBus`, `ParameterEst`) show `Not Run` in ctest (binary not built).
- Fix: `module load netlib-lapack/3.11.0-gcc` in `6_build_gridkit.sh`.

### IPOPT: `libhsl.so` not found
- An earlier build attempted to use HSL solvers (MA27/MA57) via dlopen. The expected
  `libhsl.so` does not exist on Kestrel.
- Fix: switched to MUMPS (open-source, ships via ThirdParty-Mumps). Fully functional;
  no licensing issues.

### `cmake/3.29.2` only works on RHEL 8
- The `cmake/3.29.2` module on Kestrel is linked against RHEL8 glibc and crashes on
  RHEL9 nodes.
- Fix: use `cmake/3.27.9` on RHEL9 compute nodes.
